# ADR-0001: Stack and pinned versions

- Status: Accepted
- Date: 2026-10-01
- Phase: 0
- RFC: [RFC-0001](../../rfcs/0001-ndop-ui.md), "Monorepo structure and tech stack", "Nx-first workflow"

## Context

RFC-0001 lists the stack as intent and requires the exact versions to be
checked and recorded here before Phase 0 work starts. The starting point is an
Nx workspace generated with the Angular preset:

- Yarn 1.22.22 (`yarn.lock`, `.yarnrc`, `.yarn/releases`), not pnpm.
- Nx 23.2.1, Angular `~22.1.0` (22.1.8 installed), TypeScript 6.0.3,
  Vitest 4.1.11, ESLint 9.
- One app, `apps/docs`, generated by `@nx/angular:application` with SSR
  (`@angular/build:application`, `outputMode: "server"`, an Express
  `server.ts`, `app.routes.server.ts`). It contains only the Nx welcome page.
- `tsconfig.base.json` has `strict: false` and no `noUncheckedIndexedAccess`.

All versions below were read from the npm registry on 2026-10-01 (`npm view
<pkg> dist-tags`, `peerDependencies`, `engines`), and the Analog generators were
read from the published `@analogjs/platform@2.7.5` tarball.

### Version policy

- Toolchain dependencies are pinned to exact versions in the root
  `package.json` (no `^` or `~`), so CI and every developer resolve the same
  tree. pnpm is configured to save exact versions.
- Upgrades go through `nx migrate` (Nx, Angular, Vitest, ESLint) and are
  recorded by amending this ADR's tables in the same PR.
- Published `@ndop/*` packages declare peer ranges covering both supported
  Angular majors (`^21.0.0 || ^22.0.0`); the exact pins above apply only to this
  repo.

### How `apps/docs` becomes an Analog app: regenerate

`apps/docs` is removed with `nx g @nx/workspace:remove docs` and regenerated
with `nx g @analogjs/platform:application docs --addTailwind --linter=eslint
--tags=...`, after `--dry-run` review.

Reasons, from the generator sources in `@analogjs/platform@2.7.5`:

- The conversion path, `@analogjs/platform:init` (alias `migrate`), is
  documented as "Migrate and configure an Angular SPA to use Analog". The
  current app is not an SPA: it has an Express `server.ts`,
  `app.routes.server.ts` and `outputMode: "server"`. `init` overwrites
  `main.server.ts` and `app.config.server.ts`, but leaves the Express server
  and Angular SSR server routes in place, and adds a sample
  `src/server/routes/api/v1/hello.ts`. Converting would mean hand-deleting
  generator leftovers.
- The application generator is the supported path. It runs
  `@nx/angular:application` itself (standalone, `ssr: false`, esbuild,
  `unitTestRunner: none`), then the same `init` generator with Vitest, then
  the Tailwind v4 setup. Regenerating produces exactly what Analog's
  maintainers test.
- The app holds no work: only the Nx welcome component.
- The generator reads `appsDir` from the workspace layout, which is `apps` in
  this workspace, so the project lands at `apps/docs` with project name `docs`.

Consequences of regenerating, accepted here:

- The Express server, `@angular/ssr` Express wiring, `express` and
  `@types/express` go away; Analog serves and prerenders through Nitro.
- The generator adds Analog's content dependencies (`marked`, `prismjs`,
  `mermaid`, `front-matter`, `marked-*`). They stay until Phase 3 replaces Prism
  with Shiki as the RFC requires.
- The generator writes `apps/docs/AGENTS.md` and `apps/docs/CLAUDE.md` with
  Analog conventions. They are reviewed in the dry run; they are kept only if
  they agree with the root `CLAUDE.md`.
- `docs` runs unit tests through `@analogjs/vitest-angular`, while Angular
  libraries use `@nx/angular`'s `vitest-angular` runner (Angular's
  `@angular/build:unit-test`). Both run Vitest 4.1.11.

### RFC folder tree mapped to Nx conventions

The Angular preset uses `tsconfig.base.json` path aliases, not the TypeScript
project-references layout. Ndop keeps path aliases because Angular libraries
and ng-packagr expect them. Nx generators accept an explicit `--directory`, so
the RFC tree maps one-to-one, with these additions:

| RFC location                                                 | Nx project         | Generator                           | Notes                                                                            |
| ------------------------------------------------------------ | ------------------ | ----------------------------------- | -------------------------------------------------------------------------------- |
| `apps/docs`                                                  | `docs`             | `@analogjs/platform:application`    |                                                                                  |
| (not in RFC) `apps/docs-e2e`                                 | `docs-e2e`         | `@nx/playwright:configuration`      | Nx's convention puts e2e tests in a sibling project.                             |
| `apps/harness`                                               | `harness`          | `@nx/angular:application`           | Phase 1.                                                                         |

## Consequences

- The repo moves from Yarn to pnpm: `yarn.lock`, `.yarnrc` and `.yarn/` are
  deleted and `pnpm-lock.yaml` and `pnpm-workspace.yaml` are added. pnpm must
  be installed on developer machines (Node 25+ no longer bundles Corepack).
- Vitest 5 and TypeScript 7 are known, deliberate lags behind npm `latest`.
- Every later phase that installs a package from the "later phases" table
  re-checks its version and amends this ADR.

## Implementation notes (Phase 0)

Facts found while applying this ADR; none changes a decision above.

- `nx.json` sets `workspaceLayout: { appsDir: "apps", libsDir: "packages" }`.
  Without it, the Analog generator placed the app at the repo root once
  `apps/` was empty.
- The Analog generator also writes files it doesn't use: the
  `@nx/angular:application` component (`app.ts`, `app.html`, `app.css`,
  `nx-welcome.ts`), a v3-style `tailwind.config.ts`, a sample
  `src/server/routes/api/v1/hello.ts` and a welcome page. They were deleted;
  the app prefix is `docs`.
- pnpm 12 enforces a minimum release age by default. Angular 22.2.1 was under
  a day old, so pnpm recorded exclusions in `pnpm-workspace.yaml`; they can go
  once those versions age past the threshold.
- Nx's TypeScript plugin infers `typecheck` only for project-reference
  workspaces, so `@ndop/workspace-plugin` infers it instead (`ngc` for
  Angular projects, `tsc` otherwise).
- Generated `tsconfig.spec.json` files for Vitest projects use
  `module: esnext`: Vitest runs specs as ESM, and the CommonJS setting broke
  type-checking of `import.meta` in configs and specs.

  `devkit` 21.2.24), `@angular/cdk` 21.2.14, `ng-packagr` 21.2.7 and
  TypeScript 5.9.3, because `@angular/build` 21 requires TypeScript `<6.0`.
- **zone.js 0.16.3:** Angular's unit-test builder loads zone.js and gives
  TestBed zone change detection whenever zone.js resolves (checked in
  `@angular/build` 22.2.1 source and with a probe: `NgZone` with it,
  `NoopNgZone` without). So zone.js must **not** be installed in the
  workspace: the default test run stays zoneless and the CI variant
  installs it. Adding then removing zone.js locally leaves it recorded as
  an optional peer in `pnpm-lock.yaml`, which makes the builder try to load
  it and fail; restore the lockfile instead.
